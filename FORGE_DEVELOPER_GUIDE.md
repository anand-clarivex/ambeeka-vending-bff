## 1. The Contract: What You Own vs What You Don't

### You own (vertical code)
- `Services/` — service implementation and domain logic
- `Data/` — EF Core `DbContext`, entities, repositories, migrations
- `Models/` — request/response records and domain models
- `Controllers/` — endpoint logic, routing, validation
- `Tests/` — all test cases

### You do NOT touch (horizontal — raise a Pervaxis ticket for changes)
- `Program.cs` — app startup and Genesis module wiring
- `Extensions/ServiceCollectionExtensions.cs` — DI registration structure
- `Dockerfile`, `docker-compose.*` — container configuration
- `.github/workflows/` — CI/CD pipelines
- `.claude/guides/`, `.claude/skills/` — platform standards
- `appsettings.json` — configuration schema

If you find yourself editing a horizontal file, stop and raise a Pervaxis platform ticket.

## 3. Implementing Your Service

The scaffold provides a stub implementation (`VendingServiceService`) that returns default values and logs a warning. The app starts and runs cleanly — your task is to replace the stub logic with real business logic.

### Step 1 — Update the implementation

Open `Services/VendingServiceService.cs` and replace the stub logic:

```csharp
/*
 ************************************************************************
 * Copyright (C) 2026 Clarivex Technologies Private Limited
 * All Rights Reserved.
 ************************************************************************
 */

using Microsoft.Extensions.Logging;
using Pervaxis.Genesis.Caching;
using Pervaxis.Vpa.Vending.Data;
using Pervaxis.Vpa.Vending.Models;

namespace Pervaxis.Vpa.Vending.Services;

public sealed class VendingServiceService : IVendingService
{
    private readonly IYourDomainRepository _repository;
    private readonly ICache _cache;
    private readonly ILogger<VendingServiceService> _logger;

    public VendingServiceService(
        IYourDomainRepository repository,
        ICache cache,
        ILogger<VendingServiceService> logger)
    {
        _repository = repository;
        _cache = cache;
        _logger = logger;
    }

    public async Task<VendingServiceResponse> GetAsync(string id, CancellationToken cancellationToken = default)
    {
        var cacheKey = "vpa:vending:{id}";
        var cached = await _cache.GetAsync<VendingServiceResponse>(cacheKey, cancellationToken);
        if (cached is not null)
            return cached;

        var entity = await _repository.GetByIdAsync(id, cancellationToken)
            ?? throw new YourDomainNotFoundException(id);

        var response = entity.ToResponse();
        await _cache.SetAsync(cacheKey, response, TimeSpan.FromMinutes(5), cancellationToken);
        return response;
    }
}
```

## 5. Controller Patterns

Extend the scaffold controller at `Controllers/Controller.cs` with the full CRUD surface.

```csharp
[ApiController]
[Route("/api/v1/vending")]
[Produces("application/json")]
public sealed class VendingServiceController : ControllerBase
{
    private readonly IVendingService _service;
    private readonly ILogger<VendingServiceController> _logger;

    public VendingServiceController(
        IVendingService service,
        ILogger<VendingServiceController> logger)
    {
        _service = service;
        _logger = logger;
    }

    [HttpGet("{id}")]
    [ProducesResponseType(typeof(VendingServiceResponse), StatusCodes.Status200OK)]
    [ProducesResponseType(StatusCodes.Status404NotFound)]
    public async Task<IActionResult> GetAsync(string id, CancellationToken cancellationToken)
    {
        try
        {
            var result = await _service.GetAsync(id, cancellationToken);
            return Ok(result);
        }
        catch (YourDomainNotFoundException ex)
        {
            _logger.LogWarning("Record {RecordId} not found", ex.RecordId);
            return NotFound(new ProblemDetails { Detail = ex.Message });
        }
    }

    [HttpPost]
    [ProducesResponseType(typeof(VendingServiceResponse), StatusCodes.Status201Created)]
    [ProducesResponseType(StatusCodes.Status400BadRequest)]
    [ProducesResponseType(StatusCodes.Status409Conflict)]
    public async Task<IActionResult> CreateAsync(
        [FromBody] CreateVendingServiceRequest request,
        CancellationToken cancellationToken)
    {
        try
        {
            var result = await _service.CreateAsync(request, cancellationToken);
            return CreatedAtAction(nameof(GetAsync), new { id = result.Id }, result);
        }
        catch (YourDomainDuplicateException ex)
        {
            _logger.LogWarning("Duplicate reference {Reference}", ex.Reference);
            return Conflict(new ProblemDetails { Detail = ex.Message });
        }
    }

    [HttpPut("{id}")]
    [ProducesResponseType(typeof(VendingServiceResponse), StatusCodes.Status200OK)]
    [ProducesResponseType(StatusCodes.Status404NotFound)]
    public async Task<IActionResult> UpdateAsync(
        string id,
        [FromBody] UpdateVendingServiceRequest request,
        CancellationToken cancellationToken)
    {
        try
        {
            var result = await _service.UpdateAsync(id, request, cancellationToken);
            return Ok(result);
        }
        catch (YourDomainNotFoundException ex)
        {
            _logger.LogWarning("Record {RecordId} not found for update", ex.RecordId);
            return NotFound(new ProblemDetails { Detail = ex.Message });
        }
    }

    [HttpDelete("{id}")]
    [ProducesResponseType(StatusCodes.Status204NoContent)]
    [ProducesResponseType(StatusCodes.Status404NotFound)]
    public async Task<IActionResult> DeleteAsync(string id, CancellationToken cancellationToken)
    {
        try
        {
            await _service.DeleteAsync(id, cancellationToken);
            return NoContent();
        }
        catch (YourDomainNotFoundException ex)
        {
            _logger.LogWarning("Record {RecordId} not found for delete", ex.RecordId);
            return NotFound(new ProblemDetails { Detail = ex.Message });
        }
    }

    [HttpGet]
    [ProducesResponseType(typeof(IReadOnlyList<VendingServiceResponse>), StatusCodes.Status200OK)]
    public async Task<IActionResult> ListAsync(
        [FromQuery] int page = 1,
        [FromQuery] int pageSize = 20,
        CancellationToken cancellationToken = default)
    {
        var results = await _service.ListAsync(page, pageSize, cancellationToken);
        return Ok(results);
    }
}
```

**Rules:**
- `[ApiController]` automatically returns `ValidationProblem` (HTTP 400) on model validation failure — no need to check `ModelState` manually for bound models
- Always use `ProblemDetails` for error responses — never return plain strings
- Decorate every action with `[ProducesResponseType]` — required for accurate Swagger docs
- Log at the service layer, not the controller

## 5a. BFF Pattern (Backend for Frontend)

If this service aggregates multiple downstream APIs for a frontend, apply the BFF pattern in the service layer:

```csharp
public sealed class VendingService : IVendingService
{
    private readonly IDownstreamOrdersClient _orders;
    private readonly IDownstreamProductsClient _products;
    private readonly ICache _cache;

    // Aggregate downstream responses — shape data for UI, hide internal complexity
    public async Task<DashboardSummaryResponse> GetDashboardAsync(string tenantId, CancellationToken ct)
    {
        var cacheKey = "vpa:vending:dashboard:{tenantId}";
        var cached = await _cache.GetAsync<DashboardSummaryResponse>(cacheKey, ct);
        if (cached is not null)
            return cached;

        // Fan-out calls — run in parallel
        var (orders, products) = await (
            _orders.GetSummaryAsync(tenantId, ct),
            _products.GetActiveCountAsync(tenantId, ct)
        ).WhenAll();

        var response = new DashboardSummaryResponse
        {
            TotalOrders = orders.Count,
            ActiveProducts = products.Count,
            GeneratedAt = DateTimeOffset.UtcNow
        };

        await _cache.SetAsync(cacheKey, response, TimeSpan.FromMinutes(2), ct);
        return response;
    }
}
```

Register downstream HTTP clients in `Extensions/ServiceCollectionExtensions.cs`:

```csharp
services.AddHttpClient<IDownstreamOrdersClient, DownstreamOrdersClient>(client =>
    client.BaseAddress = new Uri(configuration["Downstream:Orders:BaseUrl"]!));
```

## 9. Testing

Use `TestBase` for integration tests, xUnit + Moq for unit tests. Target **90% coverage** — the CI pipeline gates on this.

### Unit test — service logic

```csharp
// Tests/Services/VendingServiceTests.cs
public sealed class VendingServiceTests
{
    private readonly Mock<IYourDomainRepository> _repository = new();
    private readonly Mock<ICache> _cache = new();
    private readonly Mock<ILogger<VendingService>> _logger = new();
    private readonly VendingService _sut;

    public VendingServiceTests()
    {
        _sut = new VendingService(_repository.Object, _cache.Object, _logger.Object);
    }

    [Fact]
    public async Task GetAsync_WhenCached_ReturnsCachedResponse()
    {
        var expected = new VendingServiceResponse { /* ... */ };
        _cache.Setup(c => c.GetAsync<VendingServiceResponse>(
                It.IsAny<string>(), default))
              .ReturnsAsync(expected);

        var result = await _sut.GetAsync("1");

        result.Should().Be(expected);
        _repository.Verify(r => r.GetByIdAsync(It.IsAny<string>(), It.IsAny<CancellationToken>()), Times.Never);
    }

    {

              .ReturnsAsync((VendingServiceResponse?)null);

                   .ReturnsAsync((YourDomainEntity?)null);

        var act = () => _sut.GetAsync("missing");

        await act.Should().ThrowAsync<YourDomainNotFoundException>();
    }
```

## 10. Adding a New Feature — Step-by-Step

Follow this exact order every time:

```
1. Define domain exceptions (if new failure modes)
   └── Exceptions/YourDomainXxxException.cs

2. Add request/response records
   └── Models/XxxRequest.cs, Models/XxxResponse.cs

3. Extend the service interface
   └── Services/IService.cs

4. Update entity and add migration (if schema changes)
   └── Data/YourDomainEntity.cs
   └── dotnet ef migrations add <Name>

5. Implement repository method
   └── Data/YourDomainRepository.cs

6. Implement service method
   └── Services/VendingServiceImpl.cs
   └── Add logging + tracing + metrics

7. Add controller endpoint
   └── Controllers/Controller.cs
   └── Route, ProducesResponseType, error mapping

8. Write tests
   └── Tests/Services/ → unit tests
   └── Tests/Controllers/ → integration tests

9. Verify coverage
   └── dotnet test --collect:"XPlat Code Coverage"
```

## 11. What NOT To Do

| Don't | Do instead |
|---|---|
| Use AutoMapper or Mapster | Write explicit mapping methods (see `anti-patterns-and-reflection.md`) |
| Put business logic in controllers | Move it to `VendingService` service |
| Call EF Core directly from controllers | Go through the repository interface |

| Modify `Program.cs` | Raise a Pervaxis platform ticket |

## 12. Switching OIDC Provider

Pervaxis supports any OIDC-compliant identity provider. Change `Forge:Oidc:Provider` and set `Authority` + `Audience` accordingly. No code changes required — configuration only.

| Provider | Authority URL | Audience |
|---|---|---|
| Auth0 | `https://{domain}/` | `https://your-api` |
| Supabase | `https://{project}.supabase.co/auth/v1` | `authenticated` |
| Okta | `https://{domain}/oauth2/default` | `api://default` |
| Cognito | `https://cognito-idp.{region}.amazonaws.com/{pool-id}` | `{client-id}` |

Example (`appsettings.json`):

```json
{
  "Forge": {
    "Oidc": {
      "Provider": "Okta",
      "Authority": "https://dev-123456.okta.com/oauth2/default",
      "Audience": "api://default",
      "Domain": ""
    }
  }
}
```

The `Domain` property is retained for Auth0 management API compatibility and can be left empty for other providers.
