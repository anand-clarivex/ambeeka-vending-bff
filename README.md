## Configuration

Configuration is loaded from `appsettings.json` and environment-specific overrides.
Secrets are stored in AWS Secrets Manager at `{env}/vpa/vending-service/config`.

### PostgreSQL (local development)

The API reads its PostgreSQL connection string from
`ConnectionStrings:VendingDatabase`. Keep local credentials out of tracked
configuration files; use .NET user-secrets for local development:

```powershell
dotnet user-secrets set "ConnectionStrings:VendingDatabase" "<local PostgreSQL connection string>" --project src/Pervaxis.Vpa.Vending
```

The anonymous `/health/ready` endpoint opens a PostgreSQL connection and runs
`SELECT 1`. `/health` remains a liveness check and does not require PostgreSQL.
Production connection settings should be supplied through the deployment's
secret configuration.

## Authentication

The API uses Amazon Cognito User Pools for user authentication. The client application
signs users in and sends the Cognito access token as `Authorization: Bearer <token>`.
The API validates the token signature, issuer, lifetime, `token_use`, and configured
app client ID. It does not issue login tokens itself. The local Angular origin is
configured as `http://localhost:4209` for CORS.

The current Cognito pool and app client are configured for both Development and
Production. Set `Forge__Cors__AllowedOrigins__0` to the deployed Angular origin in
Production. If the environments later use different Cognito pools or app clients,
override `Forge__Oidc__Authority` with that pool's issuer and `Forge__Oidc__Audience`
with that app client's ID. The audience setting is the Cognito app client ID for
access-token validation.
